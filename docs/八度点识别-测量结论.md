# 八度点（数字上下的点）识别问题 · 测量结论（build 18）

## 用户反馈
> 春风吹里把八度关系搞错了：原本的高音没有高、低音没有低。注意数字上方表示八度关系的点。

## 一、我们自己的链路是干净的（已用测试锁住）
| 检查 | 结果 |
|---|---|
| 简谱文本 `1 1' 1, 1,,` | 八度 `[0, 1, -1, -2]`，MIDI `[60, 72, 48, 36]` ✓ |
| MusicXML `<octave>` | `[4, 5, 3, 2]`（高音真的高、低音真的低）✓ |
| AI 事件里的 `octave` | 原样进乐谱，不被"归一化"✓ |
| 文本往返 | 八度不丢 ✓ |

→ 所以问题在**视觉模型读那些点**，不在解析/导出/排版。

## 二、原图真值（逐点放大核对）
把旋律行放大 5× 后确认（`samples/real/oct_zoom_m3.png`）：

```
1̇1̇1̇1̇ 1̇  ← 五个数字上方都有点（+1）
6  7  5  3  ← 四个数字上方/下方都没有点（0）
3̇3̇3̇3̇ 3̇  ← 都有点（+1）
```

## 三、模型实测（真 API，同一张图）
| 送图方式 | 八度分布 | 判定 |
|---|---|---|
| 整页 + 旧提示词 | `+1:143  -1:56  -2:3`（**一个 0 都没有**）| 把"没点的音"当成有点 ✗ |
| 整页 + 新提示词（强调"没点就是 0"） | `0:157  +1:3  -1:52`（**高点几乎全丢**）| 反向过冲 ✗ |
| **旋律行裁出来放大 2.4× 单独送** | `+1:32`（全判高点，`6 7 5 3` 仍错）| 数字序列全对，八度仍错 ✗ |

结论：**同一张图两次跑出相反的错**，且放大 2.4× 后仍然错 →
说明模型对"1~2 像素的小点"注意力不足，靠调提示词无法稳定解决。

## 四、这版做了什么（build 18）
1. **提示词**：八度单列一节，明确"上面 n 个点 = +n、下面 n 个点 = −n、
   右边才是附点"，并给出两条自检（整页必然同时有 0 和 ±1；单声部音域不该跨三四个八度）。
2. **自动体检 + 补救重问**（`octaveVerdict`）：四个判据
   - 一个 0 都没有（把没点的音当成有点）← 春风吹就是这个
   - 全是 0（漏看八度点）
   - 某个声部音域 > 20 半音（跨三个八度）
   - 下声部比上声部还高（八度看反）
   命中就用"你上次哪里错了"的提示词**再问一次**（推理强度提到 medium），
   并且只在结果确实变好时才采纳。
3. **一键修八度**（最实用）：点音符 → 气泡里新增 **「八度+」「八度−」**，
   一下把一个音升降一个八度（可撤销）。八度点读不准时，用户几秒钟就能改对。

## 五、后续可选方案（需要时再做）
| 方案 | 说明 | 代价 |
|---|---|---|
| 本地检测点 + 对齐纠正 | 用经典 CV 找每行数字上/下的小圆点，再和模型给的**音序**对齐，直接改 octave | 中等：要写点检测（但不需要完整识谱） |
| 按小节裁剪送图 | 裁得更小、放得更大（点达到几十像素），逐段识别再合并 | 请求数变多、合并复杂 |
| 保持现状 | 云端识别 + 自动体检 + 一键修 | 已有 |

# 补充：已实现"本地检测点 + 纠正"（build 19）

## 做法
1. 云端识别完之后，**本地再跑一遍图像分析**（纯 Dart，后台 isolate，约几秒）——
   `lib/omr/` 里本来就会把点按几何位置分成"数字右侧居中 = 附点 / 数字上或下 = 八度"，
   所以直接取它每行的（音级, 八度）读数（`lib/omr/octave_hint.dart`）。
2. 用**音级序列**把本地每一行对齐到云端的音符序列（滑动窗口匹配）：
   - 匹配率 < 55% 的行直接跳过（低音谱上下两条声部叠在一起时就会这样）；
   - 中等匹配率时，若"要改的比例 > 60%"也跳过（整行翻个个儿更像本地认错）；
   - **只有数字也一致的位置才改八度**（数字不一致说明对齐漂了，宁可不动）。
3. 只改八度，音级/节奏/时值全部保留云端的结果——云端这两项很准。

## 实测（春风吹原图 + 真 API 的识别结果）
本地读出的旋律第一行（`y=342`）：
```
7 1' 2'  3'×5  2'×4 5''  1'×5  6 7 5 3  3'×5  2'×4 5'
                                ↑ 这四个原图确实没有点 —— 本地读成 0 ✓（云端全读成 +1 ✗）
```
纠正效果：
```
对齐 79 个音，改了 23 个八度
octave=0 的占比：1%  →  13%      （真值：旋律每行 4/32 ≈ 12% ✓）
```
一眼能看出：**该低的下来了、该是中间的回到中间**。

## 合成图回归测试（`test/octave_hint_test.dart`，6 项）
| 用例 | 结果 |
|---|---|
| 渲染 `1 2̇ 3̣ 5̇`（无点/上点/下点）| 本地读数 = `[0, 1, -1, 1]` ✓ 三种都分得清 |
| 全无点的一行 | 八度全是 0 ✓（不凭空加点）|
| 对齐 + 纠正 | 只改数字一致、八度不同的位置 ✓ |

## 可关掉
`AppState.useLocalOctaveCheck = false` 可以省掉本地那一遍（几秒）；
识别完成的状态里会写「八度点本地核对：修正 N 个音 / 无需修改」，一眼能看到有没有生效。
