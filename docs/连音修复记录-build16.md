# 本轮修复记录（build 16）

## 用户报的问题
> 点击音符 → 再次点击 → 选「连音」 → 再点其他音符，结果只是选中了那个音符，没有连音符号。
> 其他功能已经没问题了。

## 根因（两个叠加）
1. **浮层标记有效期太短**
   手指点在气泡上时，代码会打一个「这一下是浮层的」标记（`markOverlay()`），
   让谱面的收尾逻辑让路。这个标记原来 **500ms 就过期**。
   手机上一次有意的点按很容易超过 500ms（加上 WebView 主线程还在跑 7MB 的
   WASM 排版引擎），松手时标记已经失效 → `pointerup` 被谱面当成「点了空白」→
   `clearEdit()` 把「等第二个音」的连音模式当场清掉 → 下一次点音符就只是普通选中。
2. **Dart 侧一个陈旧的「待恢复选中」**
   编辑之后会把「重排完把选中接回来」记下来。若之后进入「连音选点」这类特殊模式，
   这个待恢复项一旦被消费，就会用 `selectNote(..., 'position')` 把 JS 的模式重置，
   连音流程同样被打断。

## 修法
| 位置 | 改动 |
|---|---|
| `lib/render/verovio_view.dart` | 浮层标记有效期 500ms → **2.5s**；手指重新按到谱面时**立即释放**标记（不再靠超时判定） |
| 同上 | 气泡开着 / 等连音第二点时，轻点同类音符**不再清空状态**（手机上一碰就没了） |
| 同上 | 连音选点时命中容差放宽到 26px，且**不做**「粘住原音符」（本来就是要选别的音） |
| `lib/ui/score_view.dart` | 特殊模式下不抢选中；进入特殊模式时把陈旧的待恢复项丢掉 |
| `integration_test/score_edit_e2e_test.dart` | 新增「**按住 800ms 再松手**」用例（老代码在这条上会失败）；并断言 MusicXML 有 `tie` 且**画面上真的画出连音线** |

## 实测
```
按住"连音"：true → 松手：released
连音选点模式：mode=tiePick from=lipu-0-1-0-0-0
等一会儿后模式：tiePick（应当还是 tiePick）
点第二个音后：画面上连音线=1/1
连音：MusicXML tie 从 0 个变成 2 个
重排后画面上连音线：1 / 1
```
单元 184 通过 / 1 跳过；`score_edit`、`verovio`、`basic_pitch` 三个端到端全绿。
